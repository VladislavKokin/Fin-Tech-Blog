# FinTech Blog

Блог о финансах на React, Express и MongoDB. В приложении можно читать и искать статьи, регистрироваться, входить в аккаунт и оставлять комментарии. Администратор создаёт и редактирует статьи, управляет пользователями и их ролями.

Проект работает через SSR: сервер отправляет браузеру уже готовый HTML страницы, затем React подключает к нему обработчики кнопок и форм. Этот этап называется гидратацией. Внешний вид задают существующие компоненты и CSS Modules.

## Запуск проекта

Нужен Node.js версии 22.13 или новее. Рекомендуется Node.js 24.

```bash
npm install
cp -n .env.example .env
npm run dev
```

Команда `cp -n` создаёт `.env`, если его ещё нет, и сохраняет существующий файл. Перед запуском заполните настройки MongoDB, описанные ниже.

Сайт откроется по адресу http://127.0.0.1:5173. Команда `npm run dev` запускает один сервер для страниц и API. Изменения клиентского кода обновляет Vite, серверного — `node --watch`. Чтобы остановить сервер, нажмите `Ctrl+C` в терминале.

## Настройки .env и MongoDB

Строку подключения MongoDB нужно вставить в файл `.env` в корне проекта, в переменную `MONGODB_URI`:

```dotenv
MONGODB_URI=mongodb+srv://USER:PASSWORD@CLUSTER.mongodb.net/blog
MONGODB_DB_NAME=blog
JWT_SECRET=
PORT=5173
HOST=127.0.0.1
PUBLIC_ORIGIN=
WEATHER_API_KEY=
```

Замените `USER`, `PASSWORD` и `CLUSTER` своими данными из MongoDB Atlas. Для локальной базы можно использовать `mongodb://127.0.0.1:27017/blog`.

| Переменная | Для чего нужна |
| --- | --- |
| `MONGODB_URI` | Адрес MongoDB вместе с данными для подключения |
| `MONGODB_DB_NAME` | Имя базы внутри кластера; в проекте используется `blog` |
| `JWT_SECRET` | Секрет для подписи токенов авторизации; обязателен в production, минимум 32 символа |
| `PORT` | Порт сайта; по умолчанию `5173` |
| `HOST` | Адрес сервера; по умолчанию `127.0.0.1`, для контейнера можно задать `0.0.0.0` |
| `PUBLIC_ORIGIN` | Внешний адрес сайта при размещении за HTTPS reverse proxy |
| `WEATHER_API_KEY` | Необязательный ключ OpenWeather для блока погоды |

Непустой `MONGODB_DB_NAME` имеет приоритет над именем базы в URI. Если переменная пустая, используется имя из URI, а при его отсутствии — `test`. Оставьте `MONGODB_DB_NAME=blog`, чтобы данные попадали в нужную базу.

Подключение выполняется через Mongoose в `server/config/database.js`. Коллекции и индексы создаются после завершения подключения. В Atlas должны быть разрешены соединения с адреса сервера и выданы права пользователю базы.

Без строки подключения работает главная страница, а запросы с данными возвращают ошибку `503`. Если URI указан, но база недоступна, запуск сервера завершится ошибкой. После изменения `.env` перезапустите сервер.

Настоящие пароли и ключи хранятся в `.env`, который исключён из Git. В `.env.example` остаются только пустые настройки и безопасные значения по умолчанию.

## Как работает SSR

1. Браузер запрашивает страницу, например `/posts`.
2. Express определяет пользователя по cookie и загружает нужные данные из MongoDB.
3. `src/entry-server.jsx` создаёт отдельный Redux store для этого запроса и формирует HTML через `renderToString`.
4. `server/helpers/render-template.js` вставляет HTML и начальное состояние в шаблон `index.html`.
5. Браузер получает страницу, а `src/entry-client.jsx` восстанавливает состояние и вызывает `hydrateRoot`.
6. Дальнейшие действия пользователя обрабатывает React, обращаясь к `/api`.

Разные запросы не используют один общий Redux store, поэтому данные посетителей не смешиваются. Начальное состояние передаётся как безопасно экранированный JSON. В HTML не попадают пароли и токены.

| Маршрут | Что отображает |
| --- | --- |
| `/` | Главную страницу |
| `/posts?search=&page=1` | Статьи с поиском и пагинацией, по 9 на странице |
| `/post/:id` | Статью и комментарии |
| `/post` | Создание статьи для администратора |
| `/post/:id/edit` | Редактирование статьи для администратора |
| `/users` | Управление пользователями для администратора |

Данные этих страниц загружаются на сервере. Несуществующий адрес возвращает `404`, отсутствие авторизации — `401`, недостаточные права — `403`.

## Данные, роли и авторизация

В базе `blog` используются отдельные коллекции:

| Коллекция | Содержимое |
| --- | --- |
| `users` | Логины, хэши паролей, роли и даты регистрации |
| `posts` | Статьи, изображения, текст и даты публикации |
| `comments` | Комментарии со ссылками на автора и статью |
| `roles` | Справочник ролей, перенесённый из старой базы |

Текст статьи состоит из полей `introduction`, `body`, `conclusion`. Названия ролей и проверка прав в приложении используют общие константы из `shared/constants`; изменение коллекции `roles` вручную не меняет правила доступа.

Администратор имеет роль `0`, модератор — `1`, читатель — `2`, гость — `3`. Регистрация на сайте всегда создаёт читателя. Гость — это посетитель без авторизации.

Пароли хранятся как bcrypt-хэши. После входа сервер устанавливает JWT в cookie `token` с `HttpOnly` и `SameSite=Lax` на 7 дней. Роль пользователя проверяется по базе при запросе. Выход очищает cookie.

При пустом `JWT_SECRET` в разработке создаётся временный секрет: после перезапуска потребуется войти заново. Для production нужен постоянный секрет и HTTPS.

## API

Успешный ответ имеет вид `{error:null,data:...}`, ответ с ошибкой — `{error:"Сообщение",data:null}`. Доступ проверяется на сервере.

| Метод | Адрес | Назначение и доступ |
| --- | --- | --- |
| GET | `/api/health` | Состояние сервера и подключения MongoDB |
| POST | `/api/auth/register` | Регистрация; `{login,password}` |
| POST | `/api/auth/login` | Вход; `{login,password}` |
| POST | `/api/auth/logout` | Выход |
| GET | `/api/auth/me` | Текущий пользователь или `null` |
| GET | `/api/posts?search=&page=1&limit=9` | Поиск и список статей, до 50 записей на странице |
| GET | `/api/posts/:id` | Статья с комментариями |
| POST | `/api/posts` | Создание статьи администратором |
| PUT | `/api/posts/:id` | Редактирование статьи администратором |
| DELETE | `/api/posts/:id` | Удаление статьи и её комментариев администратором |
| POST | `/api/posts/:id/comments` | Добавление комментария авторизованным пользователем; `{content}` |
| DELETE | `/api/posts/:id/comments/:commentId` | Удаление комментария модератором или администратором |
| GET | `/api/users` | Список пользователей для администратора |
| PATCH | `/api/users/:id/role` | Изменение роли администратором; `{roleId}` |
| DELETE | `/api/users/:id` | Удаление пользователя администратором |
| GET | `/api/roles` | Список ролей для администратора |
| GET | `/api/weather` | Погода для блока в футере |

Для создания и редактирования статьи передаются `{title,imageUrl,content}`. Автор комментария определяется сервером по cookie. Удаление пользователя сохраняет его комментарии с подписью «Удалённый пользователь».

## Администратор и импорт

Для создания нового администратора после подключения MongoDB:

```bash
npm run create-admin
```

Команда спросит логин и пароль. Логин содержит 3–15 латинских букв, цифр или `_`. Пароль содержит 8–20 символов, заглавную букву, цифру и специальный символ из `-#$%!@&*?`. При занятом логине команда вернёт ошибку.

Импорт только статей из `data/posts.json`:

```bash
npm run import-posts -- ЛОГИН_АДМИНИСТРАТОРА
```

Проверка полного старого JSON без подключения к базе и последующий перенос:

```bash
npm run import-db -- --check /путь/к/старому/db.json
npm run import-db -- /путь/к/старому/db.json
```

Полный импорт переносит пользователей, роли, статьи и комментарии. Пароли превращаются в хэши, ссылки между записями получают новые MongoDB ID. Старые сессии исключаются, даты без часового пояса считаются UTC. Повторный запуск пропускает перенесённые записи, сохраняя изменённые данные. Старый файл с открытыми паролями не нужно добавлять в Git.

## Сборка и размещение

Сгенерируйте секрет и вставьте результат в `JWT_SECRET` файла `.env`:

```bash
node -e "console.log(require('node:crypto').randomBytes(48).toString('hex'))"
npm run build
npm start
```

В `dist/client` находятся браузерные файлы, в `dist/server` — серверная сборка React. При размещении также нужны `server.js`, папки `server` и `shared`, файлы зависимостей, установленные пакеты и настройки окружения.

В production cookie авторизации требует HTTPS. Если HTTPS обслуживает reverse proxy, задайте `PUBLIC_ORIGIN=https://blog.example.com`. В этом значении указывается только адрес сайта, без пути.

Для блока погоды можно добавить `WEATHER_API_KEY`. Ключ использует сервер; без него блок показывает недоступность погоды.

Основные команды:

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Разработка |
| `npm run lint` | Поиск ошибок оформления и использования JavaScript |
| `npm run build` | Сборка клиента и серверного React |
| `npm start` | Запуск готовой сборки |
| `npm run preview` | Запуск того же production-сервера |
