# FinTech — блог об инвестициях

Одностраничное приложение (SPA) на React: блог со статьями для начинающих инвесторов. Есть регистрация и авторизация,
роли пользователей, комментарии, создание и редактирование статей, поиск, пагинация и панель управления пользователями.

Серверная часть имитируется слоем **BFF** (`src/bff`): он работает в браузере и хранит данные в **json-server**
(`src/db.json`).

## Запуск

Нужен **Node.js 20.19+ или 22.12+** (требование Vite 8).

```bash
# 1. Установить зависимости
npm install

# 2. Запустить json-server (в отдельном терминале) — адрес API жёстко задан: http://localhost:3005
npx json-server --watch src/db.json --port 3005

# 3. Запустить приложение
npm run dev
```

Приложение откроется на http://localhost:5173.

Оба процесса должны работать одновременно: без json-server статьи, авторизация и остальные данные не загрузятся.
Для блока погоды в подвале нужен интернет (данные берутся из OpenWeatherMap).

| Скрипт | Что делает |
| --- | --- |
| `npm run dev` | dev-сервер Vite |
| `npm run build` | production-сборка в `dist/` |
| `npm run preview` | локальный просмотр production-сборки |
| `npm run lint` | проверка кода ESLint |

> json-server записывает все изменения (новые статьи, комментарии, пользователи, сессии) прямо в `src/db.json`.
> Вернуть исходные данные после проверки: `git checkout -- src/db.json`.

## Роли и права доступа

Роли заданы в [src/bff/constants/role.js](src/bff/constants/role.js): `ADMIN = 0`, `MODERATOR = 1`, `READER = 2`,
`GUEST = 3`.

| Действие | Гость | Читатель | Модератор | Администратор |
| --- | :---: | :---: | :---: | :---: |
| Просмотр главной, списка статей и статьи; поиск; пагинация | ✅ | ✅ | ✅ | ✅ |
| Регистрация и вход | ✅ | — | — | — |
| Добавление комментариев | — | ✅ | ✅ | ✅ |
| Удаление комментариев | — | — | ✅ | ✅ |
| Создание, редактирование и удаление статей | — | — | — | ✅ |
| Страница «Пользователи»: смена роли, удаление пользователя | — | — | — | ✅ |

Доступ проверяется на двух уровнях:

1. **Интерфейс.** Недоступные элементы скрываются. Закрытые страницы обёрнуты в компонент
   [PrivateContent](src/components/private-content/private-content.jsx), который показывает «Доступ запрещен», если
   роли пользователя нет в списке разрешённых.
2. **BFF.** Каждая защищённая операция сначала вызывает `sessions.access(hash, accessRoles)`: находит сессию по хэшу и
   сверяет роль её пользователя со списком разрешённых. Если проверка не пройдена, операция возвращает
   `{ error: 'Доступ запрещен!!!', res: null }` и в базу ничего не записывает.

## Страницы

| Маршрут | Страница | Доступ |
| --- | --- | --- |
| `/` | Главная: слоган и иллюстрация | все |
| `/posts` | Список статей: поиск по заголовку, карточки (изображение, заголовок, дата, число комментариев), пагинация по 9 статей, кнопка создания статьи | все; кнопка создания — только администратор |
| `/post/:id` | Статья: заголовок, вступление с изображением, основная часть, заключение, дата; комментарии | все |
| `/post` | Создание статьи | администратор |
| `/post/:id/edit` | Редактирование статьи | администратор |
| `/users` | Таблица пользователей: логин, дата регистрации, роль, действия | администратор |
| `*` | Страница 404 «Такая страница не существует» | все |

Шапка и подвал общие для всех страниц. В шапке — логотип, навигация (пункт «Пользователи» виден только
администратору), кнопка входа или логин текущего пользователя с кнопкой выхода. В подвале — контактный email и текущая
погода.

## Сценарии проверки

### Гость

1. Открыть «Статьи» (`/posts`): отображаются 9 карточек и пагинация (всего 10 статей, 2 страницы).
2. Ввести часть заголовка в поиск, например `брокер`: список фильтруется.
3. Открыть любую статью: отображается текст и комментарии, но формы для нового комментария нет.
4. Открыть `/users` или `/post`: сообщение «Доступ запрещен».
5. Открыть `/post/999`: «Такой страницы не существует». Открыть `/abc`: страница 404.

### Регистрация и вход

1. Нажать на иконку пользователя в шапке: откроется окно «Авторизация». Кнопка «Регистрация» переключает на форму
   регистрации. Окно закрывается кликом по фону.
2. Проверить валидацию (yup):
   - логин: обязателен, 3–15 символов, только латинские буквы, цифры и `_`;
   - пароль: 8–20 символов, минимум одна заглавная латинская буква, одна цифра и один спецсимвол из `-#$%!@&*?`.

   Пока в форме есть ошибка, кнопка отправки неактивна.
3. Зарегистрироваться с логином `iosiph`: «Логин уже занят, попробуйте другой».
4. Зарегистрироваться с новым логином: пользователь создаётся с ролью «Читатель» и сразу входит в систему.
5. Войти с несуществующим логином: «Пользователь не найден». Войти с неверным паролем: «Неверный пароль».
6. После входа в шапке отображается логин. После перезагрузки страницы пользователь остаётся авторизованным: данные
   хранятся в `sessionStorage` до закрытия вкладки. Кнопка выхода удаляет сессию из базы и очищает `sessionStorage`.

### Читатель (`asdqasf`)

1. Открыть статью, написать комментарий, нажать кнопку отправки: комментарий появляется под статьёй.
2. Кнопок удаления комментариев и управления статьёй нет.

### Модератор (`fdsfas`)

1. У каждого комментария есть кнопка удаления. Она открывает окно подтверждения (✓ удалить / ✕ отмена); после
   подтверждения комментарий исчезает.

### Администратор (`iosiph`)

1. **Создание статьи.** На `/posts` нажать кнопку создания. Заполнить заголовок, путь к изображению (готовые картинки
   лежат в `public/Post/posts/`, например `/Post/posts/portfel.svg`), вступление, основную часть и заключение. Нажать
   кнопку сохранения: откроется созданная статья.
2. **Редактирование.** В статье нажать кнопку редактирования (переход на `/post/:id/edit`), изменить поля, сохранить.
3. **Удаление статьи.** Нажать кнопку удаления и подтвердить: статья удаляется вместе со всеми её комментариями,
   происходит переход на главную.
4. **Пользователи.** В шапке появился пункт «Пользователи». На странице можно выбрать пользователю другую роль (кнопка
   сохранения активна, только если роль изменилась) и удалить пользователя.

## Архитектура

```
Компонент ──► useServerRequest ──► server (src/bff/operations) ──► src/bff/api ──► json-server (:3005)
    ▲                                        │
    │                                        ▼
    └──── Redux store ◄── thunk-экшены ◄── { error, res }
```

### BFF (`src/bff`)

Имитирует бэкенд. Компоненты не обращаются к json-server напрямую, только через объект `server`.

| Папка / файл | Назначение |
| --- | --- |
| `api/` | Низкоуровневые запросы к json-server, по одному на файл (`getPost`, `addComment`, `setUserRole`, …) |
| `operations/` | «Серверная» бизнес-логика: проверка прав, объединение данных (например, статья + комментарии + логины авторов), каскадное удаление. Каждая операция возвращает `{ error, res }` |
| `transformers/` | Приведение полей из формата БД (`snake_case`) к формату клиента (`camelCase`) |
| `sessions.js` | Создание, удаление и проверка сессий. Сессия — запись в коллекции `sessions` со случайным хэшем и данными пользователя |
| `constants/` | `ROLE`, `ERROR`, `PAGINATION_LIMIT` (9) |
| `utils/` | `generateDate`, `getCommentsCount` |

Операции `server`: `authorize`, `register`, `logout`, `fetchPosts`, `fetchPost`, `savePost`, `removePost`,
`addPostComment`, `removePostComment`, `fetchUsers`, `fetchRoles`, `updateUserRole`, `removeUser`.

### Хук `useServerRequest`

[src/hooks/use-server-request.js](src/hooks/use-server-request.js) берёт хэш сессии из store и автоматически передаёт
его первым аргументом в защищённые операции. Публичные операции (`register`, `authorize`, `fetchPost`, `fetchPosts`)
вызываются без него.

### Redux store

[src/store/store.js](src/store/store.js) объединяет редьюсеры и подключает `redux-thunk` и Redux DevTools.

| Ветка | Содержимое |
| --- | --- |
| `user` | `id`, `login`, `roleId` (по умолчанию `GUEST`), `session` |
| `post` | текущая статья: `id`, `title`, `imageUrl`, `content`, `publishedAt`, `comments` |
| `users`, `posts` | заготовки (списки хранятся в локальном состоянии страниц) |

Экшены: `SET_USER`, `LOGOUT`, `SET_POST_DATA`, `RESET_POST_DATA`.
Thunk-экшены: `loadPost`, `savePostAsync`, `removePostAsync`, `addComment`, `removeComment`.
Селекторы лежат в `src/selectors`.

### Прочее

- Все компоненты описывают пропсы через `prop-types`. Общие типы (`ROLE_ID`, `ROLES`, `COMMENT`, `POST`) вынесены в
  [src/constants/prop-type.js](src/constants/prop-type.js).
- Модальные окна (авторизация, регистрация, подтверждение удаления) рендерятся через `createPortal` в `document.body`.
- Поиск и пагинация выполняются на стороне json-server (`title_like`, `_page`, `_limit`). Номер последней страницы
  берётся из заголовка ответа `Link`.
- Переходы между страницами анимированы через `AnimatePresence` из framer-motion ([src/main.jsx](src/main.jsx)).

## Модель данных

Файл `src/db.json`, коллекции json-server:

| Коллекция | Поля |

## Особенности учебной реализации

- Логика «сервера» (BFF) выполняется в браузере, а json-server служит только хранилищем. Поэтому проверка прав
  демонстрирует принцип работы бэкенда, но не защищает данные: к json-server можно обратиться напрямую.
- Пароли хранятся в открытом виде.
- Даты публикации, регистрации и комментариев генерирует `generateDate` случайным образом, поэтому часть дат находится в
  будущем.
